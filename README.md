# Основание

Папка-агент для руководителя цифрового продукта. Открываете её в Claude Code или Cursor, пишете вопрос своими словами («кому продавать», «почему уходят», «что сказать клиентам») — агент ведёт работу от постановки до продуктовой и коммуникационной стратегии с планом проверки. Каждое число в стратегии ведёт к дословной цитате источника, у каждого варианта есть сильное возражение, а когда приходят новые данные, агент сам находит выводы, которые на них держались.

Работа для номинации «ИИ-проект» MGIMO AI Challenge 2026 (задача МегаФона «Стратег Фабрики продуктов»). Материалы неофициальные, используются только открытые данные.

## Проверить за три минуты, без ключей

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/) (для тестов).

```bash
make doctor   # окружение, хуки, навыки, хеши правил
make test     # 36 тестов: путь от запроса до решения, точки человека, защита
make eval     # оценки: инъекции, каналы атак, дефекты стратегии → evals/report.md
```

Что показывает `make eval` на 14.11.2026 (`evals/report.md`):

- скрытый текст страниц (display:none, комментарии, alt) не дошёл до агента ни в одной из 48 атак нового слепого корпуса;
- после всех атак точка человека G1 осталась открытой, проверенных фактов — 0;
- 15 из 15 формальных дефектов стратегии (число без ссылки, обещание без возможности, спрос только из модельных респондентов, нет базы сравнения и т. д.) блокируют утверждение;
- детектор инъекций на регулярных выражениях на новом корпусе ловит 19 из 48 атак при 7 ложных срабатываниях из 40. Это первый слой, а не защита; почему — в `evals/HISTORY.md`.

## Полный прогон

1. Установите [Claude Code](https://docs.claude.com/en/docs/claude-code) и войдите (подписка или ключ API).
2. Откройте папку и напишите задачу в чате. Первое, что сделает агент, — `bin/osnovanie resume`.
3. Отвечайте в точках G1–G4: что писать — в `docs/MANAGER.md`.

Ключи не обязательны. `TYPESAFE_API_KEY` подключает узкий классификатор Jev для маршрутизации; без него судья откатывается на haiku, затем sonnet, и это видно в журнале. Шаблон — `.env.example`.

## Как устроено

| Слой | Где |
|---|---|
| Постоянные правила | `AGENTS.md` (вход для любой среды), `instructions/quality.md` |
| Этапы и навыки | `.agents/skills/` → intake, collect, research, options, strategy, validation, review, interview, ux-review, data-analysis |
| Методики | `methods/` — 21 файл с процедурой, типичными ошибками и критерием готовности (JTBD, Rumelt, COM-B, ACH, Fermi, unit-экономика, A/B с расчётом MDE…) |
| Инструмент | `bin/osnovanie` — 38 команд: утверждения, источники, проверки, модель вариантов, точки человека, пересмотр, стоимость, реплей прогона |
| Защита | хуки `tools/hooks/claude_hook.py`: запись только в `outputs/`, точки закрывает только человек, карантин инъекций, бюджет |
| Субагенты | `.claude/agents/`: skeptic, closure-advocate, verifier, researcher, source-sanitizer, synthetic-respondent |
| Знания между проектами | `kb/`, поиск `search`, MCP `kb-state` |
| Состояние проекта | `projects/<проект>/state/` — журналы на диске, поэтому работа продолжается в новом чате |

Требования ТЗ по пунктам и команды проверки — `docs/CRITERIA.md`. Модели, ключевые промпты и ошибки ИИ при сборке — `docs/ai/`.

## Ограничения

- Демо-проект на открытых данных МегаФона в работе; до его прогона цена и время полного прохода не измерены.
- Переносимость в Cursor и Codex подготовлена (`.cursor/`, `.codex/`, `export`/`import`), но в этих средах не проверена.
- Сравнение с обычным чатом (D13) подготовлено (`evals/d13/`), но ещё не прогнано. Прогон агента на шести новых задачах (`evals/tasks.toml`) тоже не сделан.
- Агент не ходит в закрытые данные и не пишет никому от вашего имени.
