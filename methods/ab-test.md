# Эксперимент и квазиэксперимент

Источники: R. Kohavi, D. Tang, Y. Xu, «Trustworthy Online Controlled Experiments», 2020; правило Лера для размера выборки.

## Когда применять

Раздел «План проверки» (`outputs/validation.md`).

## Процедура

1. Гипотеза: «Если [изменение] для [аудитории], то [метрика] изменится на [величину] за [срок], потому что [механизм]». Механизм ссылается на утверждения.
2. Метрика решения одна, антиметрик две-три.
3. Минимальный эффект, который имеет смысл для бизнеса (MDE), — допущение, обоснованное экономикой: эффект меньше MDE не окупает вариант.
4. Размер выборки на группу при α = 0,05 и мощности 80%: n ≈ 16 × σ² / δ². Для доли p: σ² = p(1 − p). Пример: p = 0,10, δ = 0,02 → n ≈ 16 × 0,09 / 0,0004 = 3 600 на группу. Считай через `bin/osnovanie data calc` или модель, укажи допущения о p.
5. Срок = n × число групп / поток в день, но не меньше одного полного недельного цикла. Смотреть результат раньше срока нельзя, иначе растут ложные срабатывания.
6. Если рандомизация невозможна (тарифы, регионы, бренд): поэтапный запуск по регионам, разность разностей, сравнение с синтетическим контролем. Назови, какое допущение делает сравнение честным (параллельные тренды).
7. Критерии остановки: вред антиметрике выше порога, перекос групп (SRM), технический сбой.
8. Эффект новизны и сезонность назови явно.

## Типовые ошибки

Нет базового значения и не сказано «неизвестно»; MDE взят с потолка; срок короче недели; одна метрика без защитных.
