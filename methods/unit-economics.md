# Юнит-экономика

Общепринятые определения метрик подписочного продукта.

## Когда применять

Варианты (при каких допущениях вариант живёт) и раздел «Экономика» продуктовой стратегии. Обязательна для вариантов «закрыть» и «масштабировать».

## Величины (за месяц, на одного платящего)

- ARPPU — выручка на платящего; ARPU — на всех активных.
- Себестоимость обслуживания: для сервиса поверх чужих моделей это прежде всего стоимость запросов к моделям, поддержка, платёжная комиссия.
- Маржа = (ARPPU − себестоимость) / ARPPU.
- Отток m — доля платящих, ушедших за месяц. Средний срок жизни ≈ 1 / m месяцев.
- LTV ≈ ARPPU × маржа / m.
- CAC — затраты на привлечение одного платящего. Окупаемость = CAC / (ARPPU × маржа), месяцев.
- Конверсия бесплатный → платный.

## Процедура

1. Для каждой величины найди основание. Публичных данных о закрытых метриках компаний почти никогда нет: тогда это `assumption` с диапазоном low/base/high и объяснением, откуда диапазон (аналог, отраслевой ориентир, расчёт из тарифа).
2. Цену бери из тарифа как факт с цитатой. Себестоимость запроса считай из публичных цен поставщиков моделей, если они есть, с датой.
3. Собери модель: `bin/osnovanie model set --file outputs/tmp/model.json`, формулы на величинах, единицы указаны. Команда проверит размерности.
4. `bin/osnovanie model run`: смотри не только базу, но диапазон p10–p90, долю случаев, где вариант лидирует, и порог смены лидера.
5. В тексте назови 1–2 допущения, от которых результат зависит сильнее всего, и как их проверить быстрее всего.

## Мост прибыли к цели и окупаемость (когда задана цель по валовой прибыли)

1. База — прибыль при обычном обслуживании за тот же год, одна для всех вариантов. Разрыв = цель − база (285 − 279 = 6 млн руб.).
2. Вклад удержания = Σ по месяцам планового года (платят при новом − платят при обычном) × прибыль за оплаченный месяц номера. Без новых расходов граница решения = разрыв / прибыль за месяц (6 млн / 500 руб. = 12 000 дополнительных оплаченных месяцев). Работа, начатая в последнем месяце года, даёт в этом году не больше одного месяца на номер.
3. Новые прямые расходы вычитаются, поэтому с ними месяцев нужно больше. Экономия поддержки считается только по затратам, которые действительно исчезнут; освободившееся время сотрудников без снижения расходов — не деньги, а отдельная строка «куда пойдёт время».
4. Привлечение без двойного счёта: на начало года + новые подключения − выбывшие; канал каждого подключения закреплён заранее; в эффект идёт только прирост к обычному обслуживанию. Стоимость дополнительного подключения = расходы канала / прирост к обычному обслуживанию.
5. Разработка отдельно: по кварталам накопленная прибыль после прямых расходов против накопленных вложений; квартал, где первая догоняет вторые, — расчётная окупаемость. Пока стоимость разработки неизвестна — предельная сумма вложений, которая вернётся за выбранный срок. Деньги после конца года относятся к следующим годам.
6. Показать, что будет при более слабом спросе, удержании или более дорогом обслуживании, и назвать значение, которое предстоит узнать, если граница зависит от неизвестной цены.

В модели (`model set`) это величины: база, прибыль за месяц, дополнительные месяцы, прямые расходы, исчезающие затраты поддержки; формула варианта — база + месяцы × прибыль за месяц + экономия − расходы, единица — руб./год. Порог смены лидера по «дополнительным месяцам» и есть граница решения.

## Типовые ошибки

- Точное число там, где известен только порядок.
- LTV без маржи (по выручке).
- Месячный отток смешан с годовым, период не указан.
- Экономика варианта «оставить как есть» не посчитана.

## Готово, если

Каждая величина модели связана с утверждением, допущения названы, диапазон показан, у варианта есть условие, при котором он убыточен.
