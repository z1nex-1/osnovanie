# D13: агент против обычного чата

ТЗ просит измерить, насколько агент быстрее, дешевле или точнее обычного чата с ИИ и какой ценой. Здесь это измеряется на одних и тех же входных данных, и оценки ставятся вслепую.

## Как устроено сравнение

| | Агент | Чат без поиска | Чат с поиском | Чат с теми же материалами |
|---|---|---|---|---|
| Модель | настоящий прогон 19.11: этапы на Sonnet 5.5, оркестрация на Opus 5.5 (раунды 1–3 t1 — эталон `meganeuroseti-ref`) | Claude Opus 5.5 | Claude Opus 5.5 | Claude Opus 5.5 |
| Вопрос | из `evals/tasks.toml` | тот же | тот же | тот же |
| Материалы | источники, найденные агентом в прогоне | нет | поиск в интернете | `materials.md`: те же 27 цитат одним текстом |
| Требования к результату | навыки этапов | тот же список из `rubric.toml` прямо в запросе | то же | то же |
| Человек | ответы в точках G1–G4 даёт оператор прогона, сессия Claude в роли руководителя, не человек | не участвует | не участвует | не участвует |

Чату дают те же требования, что и судьям. Если чат получит вопрос без требований, сравнение будет с заведомо слабым противником, и выигрыш агента ничего не скажет.

Агентская рука t1 с раунда 4 и рука t2 — настоящие прогоны 19.11 (`docs/LIMITS.md`, «Живые прогоны агента»). Ответы в их точках давал не человек, а оператор прогона, то есть сессия Claude Code в роли руководителя. В раундах 1–3 t1 агентской рукой был эталонный проект.

Руки чата прогнаны свежими субагентами Claude Code на Opus 5.5 без доступа к репозиторию и записаны командой `record`. Время и токены сняты с субагента, цена посчитана по прайсу и помечена как оценка.

Чат с материалами в t1 видел 27 цитат эталона. В t2 он видел тексты источников агента, каждый обрезан до 12 000 знаков (`prepare --per-source 12000`): полмиллиона знаков не помещаются в окно. Правило задано до прогона и одинаково для всех источников.

## Порядок

```bash
python3 evals/d13/d13.py prepare t1-meganeuroseti --project meganeuroseti-ref
python3 evals/d13/d13.py prompt t1-meganeuroseti            # запросы трёх рук в prompts/
python3 evals/d13/d13.py chat t1-meganeuroseti --arm web    # или record, если ответ получен в другом окне
python3 evals/d13/d13.py agent t1-meganeuroseti --project meganeuroseti-ref
python3 evals/d13/d13.py blind t1-meganeuroseti
python3 evals/d13/d13.py judge t1-meganeuroseti --judge sonnet
python3 evals/d13/d13.py judge t1-meganeuroseti --judge ollama:yandexgpt-lite:8b
python3 evals/d13/d13.py judge t1-meganeuroseti --judge ollama:qwen3.5:9b
python3 evals/d13/d13.py score
```

- `blind` убирает признаки авторства. Внутренние номера утверждений агента превращаются в сноски с цитатой, так что судья видит, на что опирается вывод, но не видит, кто автор. Для каждой руки работы получают буквы X и Y в случайном порядке, ключ кладётся отдельно в `key.json`.
- `judge` показывает судье пару дважды: X перед Y, потом Y перед X. Если при смене порядка судья меняет предпочтение, в отчёте это помечено как «неустойчив к порядку», и такое предпочтение не считается. К каждой оценке судья приводит дословную фразу из обеих работ; `score` проверяет, что фраза действительно есть в тексте.
- Судьи: Sonnet (та же семья, что и обе работы) и две локальные модели других семей через Ollama — YandexGPT-5-Lite 8B и Qwen 3.5 9B, от трёх до пяти минут на вызов, без сети и без ключей.
- `human.toml` — та же рубрика для оценки человеком. Ключ открывается только после оценки.
- `score` собирает `report.md` и `results.json`: баллы по рубрике, цену, долю чисел, которые находятся в материалах, пункты, где агент проиграл, и таблицу раундов из `runs/<задача>/round-*`.

## Ограничения

- Раунды 2 и 3 — подгонка: агентскую работу правили по замечаниям судьи, работы чата не менялись. Честный результат — раунд 1. Что правили — `runs/t1-meganeuroseti/ROUNDS.md`.
- В цену агента входят повторы, правки по точкам и сессия оператора, а в цену чата — один ответ. Цифры несопоставимы один к одному: агент делает больше работы.
- В t1 `materials.md` — эталонные цитаты плюс цитаты настоящего прогона (раунд 4b). Без них судьи не могли проверить числа агента (раунд 4a).
- Сверка чисел механическая: число из фразы ищется в тексте материалов. Совпадение короткого числа может быть случайным. Расчёт, которого нет в материалах, попадает в «не найдено» и проверяется вручную по списку `untraced`.
- Локальные судьи на 8–9 млрд параметров слабее Sonnet: их оценки смотрятся как проверка на другой семье, а не как главный счёт.
- Адаптер облачного YandexGPT (`--judge yandex`) написан по документации и не проверен на настоящем ключе.
- Материалы для судьи обрезаются до 60 тысяч знаков.
- Время чата — время одного ответа модели. Время человека, который читает и дорабатывает ответ чата, не измерено.
